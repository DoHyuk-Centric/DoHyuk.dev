# 커밋 메시지 컨벤션

## 형식

```
타입: 제목 (#이슈번호)

(선택) 본문 — 왜 이 변경이 필요했는지
```

- **한 커밋 = 한 목적**. 서로 다른 이유로 바뀐 변경 사항을 한 커밋에 섞지 않는다
- 제목은 명령형으로, 끝에 마침표를 붙이지 않는다
- 이슈 번호가 있는 작업이면 `(#이슈번호)`를 붙인다. 없으면 생략 가능

## 타입

| 타입 | 의미 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서만 변경 (코드 영향 없음) |
| `chore` | 빌드/설정/의존성 등 잡무성 변경 |
| `refactor` | 동작은 그대로, 코드 구조만 변경 |
| `test` | 테스트 추가/수정 |
| `merge` | 브랜치 병합 |

## 예시

```
feat: 게시물 검색 API 추가 (#12)
fix: SQLite 동시 쓰기 시 락 걸리는 문제 수정 (#20)
docs: git-flow, commit-convention 문서 작성 (#1)
chore: pnpm workspaces로 모노레포 전환
chore: EC2 배포 워크플로우 추가
```

## Pre-commit 훅과의 관계

코드 변경이 포함된 커밋은 `.husky/pre-commit`이 typecheck·단위 테스트·E2E 테스트를 자동으로 돌린다. 이 검증을 우회하려고 `--no-verify`를 쓰지 않는다 — 실패하면 원인을 고치고 다시 커밋한다.
